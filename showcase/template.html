Architecture

From source system to a decision

Row-level logic lives in Snowflake, aggregation logic in DAX, and access is defined once for both.

Sources ingest

  • CMMS work orders via Snowpipe
  • Asset master data from the Power Apps CRUD app
  • HR technician list
  • Controlling budget

Snowflake RAW · SILVER · GOLD

  • Dynamic tables with freshness targets
  • DQ flags, never silent drops
  • SCD2 assets, point-in-time joins
  • Masking and row-access policies
  • 9 automated DQ tests, hourly

Power BI certified

  • Star schema, single-direction only
  • 38 measures as code

Engineering details a reviewer will ask about

What makes it production-grade

Measures as code

One YAML file generates the TMDL script, the DAX query view script and the business KPI catalogue, so they cannot drift apart.

Numbers proven before certification

CI queries the published model through the REST API and fails if any KPI deviates more than 0.1 % from the independent reference.

Security defined once

Snowflake row-access policies and Power BI RLS read the same entitlement table, with ticket IDs and expiry dates for quarterly re-certification.

Audit-proof CRUD app

Temporal tables keep every version for 10 years, the app can only call procedures, and a constraint makes self-approval of critical changes impossible.

Best Practice Analyzer gate

14 rules covering performance, DAX style, naming, descriptions and PII protection. Severity 3 blocks the merge.

Coaching with a measurable path

Four levels from consumer to champion, a graded mini-project before build rights, and adoption KPIs such as share of views on certified content.
